The target is native Linux computer use and external Chrome control without a Codex sign-in, using original app 26.915.31945 / CUA 0.0.16. This development checkout is **not release-ready**. The thin installer, native path, local instruction delivery, and an installed no-sign-in Chrome action pass on an ARM64 Ubuntu AppArmor host; the Chrome action also passes in an emulated x86-64 Ubuntu VM. In the default browser path, the original service starts a Codex user-identity fetch to initialize Statsig. On a fresh extension profile, `agentRequestHeaderEnabled` is `false`, so the first relevant session request also reads the user-specific `codex_browser_use_agent_request_header` gate. LCU's relay reports `true` to that service for this one reply. The service then skips the gate lookup on this path; its background identity initialization still starts. The official extension applies Chrome rules that add `x-browser-agent: ChatGPT/<session ID>` to agent-controlled tab requests. This is a website-visible label, not a login token or signed identity proof. The pinned code does not document why OpenAI added this header. LCU makes a local header-on decision with the user's explicit authorization; original MCP origin approval remains active. See the [verification record](verification/installed-app-2026-09-23.md).

The old in-app browser, cloud/Orbit backend provisioning, private account/workspace UI and a Silo annotation extension are outside this release. Copied instruction and embedded-browser source was removed from the working tree. The existing full-copy commit remains reachable from the remote `fix/full-linux-parity` branch; a new direct-main push must not include that commit. No release or push is authorized by these fixture results.
