# Installed-app migration status

The target is native Linux computer use and external Chrome control without a Codex sign-in, using original app 26.915.31945 / CUA 0.0.16. This development checkout is **not release-ready**. The installed native desktop and no-sign-in Chrome paths passed on Ubuntu 24.04.5 ARM64 and on an isolated KVM guest running on physical AMD x86-64 hardware, with AppArmor active on both. The copied-source commit has been removed from the new local main lineage. Independent agent-product checks exposed browser compatibility gaps in OpenCode and Goose. The Chrome header decision is a local LCU policy override, not an exact Codex account feature-gate result.

In the default browser path, the original service starts a Codex user-identity fetch to initialize Statsig. On a fresh extension profile, `agentRequestHeaderEnabled` is `false`, so the first relevant session request also reads the user-specific `codex_browser_use_agent_request_header` gate. LCU's relay reports `true` to that service for this one reply. The service then skips the gate lookup on this path; its background identity initialization still starts. The official extension applies Chrome rules that add `x-browser-agent: ChatGPT/<session ID>` to agent-controlled tab requests. This is a website-visible label, not a login token or signed identity proof. The pinned code does not document why OpenAI added this header. LCU makes a local header-on decision with the user's explicit authorization; original MCP origin approval remains active. See the [verification record](verification/installed-app-2026-09-23.md).
