# Hermes Agent harness integration

The Hermes adapter was checked against NousResearch Hermes Agent v0.21.5, source commit `749220ef0007f8d87bd1531f1c24b0fe93816385`, installed on macOS on 2026-09-28. The checked-out Hermes source was inspected read-only; tests use a disposable `HERMES_HOME` and synthetic MCP server, with no personal desktop or credentials.

## Upstream interfaces

Hermes documents MCP servers as stdio or HTTP integrations in [`~/.hermes/config.yaml`](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp). Direct MCP registration does not give an MCP tool handler a supported hook for forwarding Hermes' exact session and turn IDs to the original CUA server. Hermes' native [Python plugin API](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins) exposes `register_tool`, `pre_llm_call`, `on_session_end`, and `register_skill`; the [hook reference](https://hermes-agent.nousresearch.com/docs/user-guide/features/hooks) records `session_id` and `turn_id` at turn start and canonical turn finalization. The installed source at the cited commit implements the same contracts in `hermes_cli/plugins.py`, `tools/registry.py`, and `agent/turn_finalizer.py`.

LCU therefore installs an opt-in native Hermes plugin. Its model-visible `js` and `js_reset` tools are backed by the original runtime through the shared `adapters/client.mjs` MCP SDK client in a persistent Node bridge. The bridge forwards original tool descriptions, initialization instructions, call results, and exact session/turn/tool-call metadata. The plugin injects the generated LCU skill and original context before each model turn, and forwards turn finalization as original `Stop` or `Interrupt` cleanup. The plugin retains failed cleanup identities and retries them before enabling a later turn. A single Hermes process may own only one live CUA session at a time; switching to another sequential session closes and reconnects the runtime to clear its JavaScript state. Concurrent sessions fail closed.

Hermes' `tools.approval_prompt.request_elicitation_consent` is the existing host UI seam. LCU uses that per-call consent flow and maps acceptance only to the original one-time response; it never turns an answer into a session or permanent grant. Hermes consent can display a decision, not fill arbitrary elicitation fields, so unsupported schemas and URL-mode requests are canceled. If Hermes' UI does not return a decision, LCU cancels the original request.

Text and error-only results retain their original MCP result envelope, including `isError`. For image results, the adapter preserves the original bytes in Hermes' native `image_url` content part without resizing or re-encoding; the text fallback reports the MIME type rather than duplicating base64. Audio blocks are saved byte-for-byte through the shared `audio-files.mjs` helper and returned as local paths, matching LCU's other harnesses. Unsupported image-containing block kinds fail closed rather than being flattened into invented text.

## Verification

`tests/test_hermes_harness.py` exercises the plugin against a local stdio MCP fixture. It checks descriptor and instruction delivery, generated-skill registration, exact LCU turn metadata, a one-time native-app approval, fail-closed form elicitation, exact image bytes, audio file bytes, cross-session exclusion, and retry after a failed `Stop` cleanup. It runs the fixture beside the adapter dependencies from the built LCU release, so source checkouts do not need checked-in `node_modules`.

The installed Hermes CLI also passed the reproducible `HERMES_BIN=/path/to/hermes python3 tests/hermes_registration.py` check against a temporary `HERMES_HOME`, temporary `HOME`, and local MCP fixture. Hermes 0.21.5 reported: “OK: runtime discovery, manifest parsing, import, and registration passed; registrations: 2 tool(s), 2 hook(s).” The plugin manifest declares the same two tools and two hooks, so the native doctor emitted no capability warnings. This checks Hermes' actual plugin loader and registration path. It does not prove that a model provider received or interpreted image/audio content or that a desktop CUA action completed. Those behaviors require a real Hermes model/desktop integration run and are not claimed here.

The final `tests/run.sh linux/arm64` gate passed with the verified pinned local package: 214 Python tests, offline installation, existing Codex/Claude Code/Pi registration checks, and the disposable Linux GTK desktop suite. Evidence archive: `.verification/arm64.5fnpEe`. The 16 focused Pi/OMP adapter tests passed. The broader Node adapter run had an intermittent Codex progress-notification assertion failure; the unchanged HEAD Codex fixture passed in isolation, so the broader suite is not recorded as green. These checks do not extend OMP or Hermes desktop claims.
