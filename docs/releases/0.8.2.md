# LCU 0.8.2

This release fixes computer use on Linux machines where the original Node REPL can sandbox its children, and records why GTK 4 windows ignore window-targeted keys and clicks. It adds no new harness verification claims and no new tested app pairs; Windows remains deferred.

## Changes

- **Linux: computer use works where the original sandbox is active.** On a machine with bubblewrap and user namespaces, the original `node_repl` ran Sky under a network-disabled `codex sandbox` unless the host sent `codex/sandbox-state-meta`. Its seccomp filter refused the connection to the X11 socket, so every `js` call failed with `Could not connect to X11 ... Operation not permitted` while `lcu doctor` passed. None of LCU's adapters (Codex relay, Claude relay, Pi, Oh My Pi, Hermes) or generic MCP clients send that metadata, so all of them were affected. `lcu` now adds the same disabled sandbox state official Codex sends under `danger-full-access` to the original `NODE_REPL_REQUEST_META` on Linux. A host that sends its own `codex/sandbox-state-meta`, per call or in that variable, keeps precedence, so a deliberately stricter profile is honored. `LCU_NODE_REPL_SANDBOX=host` declines the default. Original approvals are unchanged. See [Linux sandbox state](../ADAPTERS.md#linux-sandbox-state).
- **GTK 4 input is documented, not changed.** The original engine delivers window-targeted keys and coordinate clicks with `XSendEvent`, which GTK 4 (XInput2 only) ignores; AT-SPI actions, `typeText` and `paste` work, and desktop-level `sky.press_key`/`sky.click` after `sky.activate_window` reach GTK 4. LCU adds no input implementation. The [verification note](../verification/linux-sandbox-and-gtk4-input-2026-10-02.md) lists the session requirements.
- **Tests.** The Docker gate now runs the GTK oracle flow through a bare client, the Codex relay, the Claude relay, the shared Pi/Oh My Pi client and the Hermes bridge with no sandbox metadata, in a container where the sandbox is active (negative control included), and adds a GTK 4 fixture. `tests/codex_sandbox_state.py` records what a Codex CLI sends under each sandbox mode.
