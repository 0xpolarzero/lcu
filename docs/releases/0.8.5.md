# LCU 0.8.5

This release shrinks and hardens the Linux window-targeted input translation after a second review of 0.8.4. It adds no new harness verification claims and no new tested app pairs; Windows remains deferred.

## Changes

- **Held keys are no longer translated.** `key_down` and `key_up` now always go to the original service unchanged, and the hold bookkeeping is gone. 0.8.4's claim that translated holds were "always released" was wrong (see the correction in the [0.8.4 notes](0.8.4.md)): partial chord releases, key aliases such as `Shift` and `Shift_L`, a failed release and turn cleanup could all leave a modifier held. On a GTK 4 window a held key now behaves as in the original engine, which delivers it with `XSendEvent` and so is ignored. To hold a key for a GTK 4 window, activate it and use the desktop-level `key_down`/`key_up` (no `window`). `press_key` (atomic chords, with the original engine owning the whole chord), `click` (including double), `scroll`, `drag` and `move` stay translated for GTK 4, and `scroll` for Qt.
- **Everything that can change focus or input runs through one queue.** `activate_window`, desktop-level input, window-targeted input of every kind, `typeText`, pass-through fallbacks and untranslated calls are serialized with translated requests, so nothing interleaves between a translated request's final focus check and its input (an `activate_window` of another window could previously move a key to that window). Read-only calls (`list_windows`, `list_apps`, `get_screenshot`, `get_window_state`) bypass the queue. The focus is still verified immediately before the desktop-level call.
- **Window ownership comes from the X server.** `_NET_WM_PID` is the client's own claim in its own PID namespace, so a client sharing the X socket from another namespace (Flatpak, containers) could advertise an id that collided with an unrelated local process. LCU now asks the X server (X-Resource `XResQueryClientIds` with the PID mask, the `SO_PEERCRED` id; nothing for a remote client) and translates only when it equals `_NET_WM_PID`, the machine is this host and the process shares LCU's PID namespace. Anything else, or an unavailable query, fails closed to the original behavior.
- **New system package: `libxres1`** (X.org X-Resource client library, about 7 kB, Ubuntu `main`) was added to the installer's `SYSTEM_PACKAGES`. Silo's image needs it as well; without it, or without `python3`, GTK 4 and Qt windows behave as in the original engine.
- `LCU_LINUX_INPUT_TRANSLATION=off` and the per-pair `native_input` switch are unchanged. See [Linux window-targeted input](../ADAPTERS.md#linux-window-targeted-input) and the [verification note](../verification/linux-input-translation-2026-10-02.md#085-smaller-translation-authoritative-process-identity).
