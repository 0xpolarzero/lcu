# LCU 0.8.0

This release makes the Linux install lighter, tells you whether the app you have is one LCU tested, and adds an optional, reversible switch that removes the harness's per-call prompt for LCU's tools. It adds no new harness verification claims; Windows remains deferred.

## Changes

- **Linux uses the installed app in place.** The installer used to copy the whole ChatGPT app (about 1.5 GB) into a private generation under `<prefix>/apps`. It now validates `/usr/lib/chatgpt` (or `--existing-app PATH`) where it is, links each release to it, and reports the version and runtime it observes, as macOS already did. Updating the app through apt updates what LCU uses; restart agents afterwards. `lcu prune` reclaims copies made by 0.7.0 and earlier. Windows keeps its private copy.
- **Tested app and runtime pairs.** App versions are date stamps and the CUA runtime is `0.0.x`, so neither signals compatibility. `tested-versions.json` records the exact pairs LCU's verification covers, with the LCU version that tested each. `lcu setup`, the installer's `--runtime-only` mode and `lcu doctor` report whether the selected pair is tested and print a warning for an untested one. The warning never blocks: LCU still uses the app.
- **`lcu status [--json]`** prints the installed LCU version, the selected app and runtime, the tested state (`compatibility.status` is `tested`, `untested` or `unknown`; `compatibility.tested` is `true`, `false` or `null`) and the saved setup, without needing a desktop session.
- **Approval mode: `lcu setup --approval auto|ask`.** `auto` adds only LCU's own entries to each selected harness so its tools run without a per-call prompt: Claude Code `permissions.allow: ["mcp__lcu"]`, Codex CLI `default_tools_approval_mode = "approve"` on `[mcp_servers.lcu]`, and Oh My Pi `tools.approval` `js` and `js_reset` set to `allow`. Pi and Hermes have no gate on LCU's tools, so nothing is written. `ask` (the default) removes exactly what `auto` added and leaves harness defaults. The choice is remembered per account in `setup.json`; a later setup keeps `auto`, and only an explicit `--approval ask` removes entries. Native-app and Chrome approvals come from the original runtime and are unchanged, and Chrome site approvals remain exact-origin only. See [approval mode](../INSTALLATION.md#approval-mode).
