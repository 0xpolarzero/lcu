# Dependency provenance

LCU installs the official ChatGPT Linux application 26.915.31945 as a private dependency on the target Linux machine. Its CUA runtime is 0.0.16/20260915001755-492f19756c31. The package URL template, ARM64 and amd64 SHA-256 digests, and a small architecture-specific critical-file hash set are in [runtime.lock.json](../runtime.lock.json). The digest is checked before extraction; this is an integrity pin, not independently verified package-signature authentication.

The inspected .deb control metadata says Package=chatgpt, Version=26.915.31945, with Architecture=arm64 or amd64. The app lives at usr/lib/chatgpt inside the package and contains the unchanged resources/cua_node runtime, resources/codex and resources/codex-code-mode-host, plugin tree, Electron application and original notices. LCU stages the complete package payload under its versioned managed prefix. It does not run the package maintainer scripts or register the app with apt.

The pinned package post-install script writes an OpenAI apt key/source and loads an AppArmor profile. That profile is bound to /usr/lib/chatgpt/ChatGPT, the original Electron UI executable, and grants userns to it. LCU launches the selected app's Node/REPL directly, without running that post-install script. An Ubuntu 24.04.5 ARM64 VM with AppArmor active passed the installed native fixture and later passed a no-sign-in Chrome action using LCU's relay. Earlier process sampling found Node/REPL `unconfined`, Chrome and the extension host `chrome (unconfined)`, and nonblocking `bwrap` capability denials. Chrome launched without `--no-sandbox`. See the [exact verification record](verification/installed-app-2026-09-23.md). Native x86-64 host behavior remains unverified.

The original Chrome provider and native messaging host come from resources/plugins/openai-bundled/plugins/chrome in this same installed app. Its native-host installer writes beside its executable; LCU copies that plugin to the target account's writable data directory during browser setup, runs the original installer there, and points the account's manifest at LCU's small relay. The relay locally enables the official extension's agent request label. The official extension and a compatible browser are installed or enabled by the desktop user. [OpenAI's extension documentation](https://learn.chatgpt.com/docs/chrome-extension) gives its supported setup flow. [Google's Chrome Linux guide](https://support.google.com/chrome/answer/95346?hl=en) lists both x86-64 and ARM64 packages. Extension discovery alone does not prove browser action.

The build fetches separately pinned third-party agent registration tools defined in scripts/agent-tools/package-lock.json. Their temporary build Node is discarded; setup uses the selected official app Node. These tools and LCU code may appear in a thin archive, subject to their own licences. Original OpenAI app binaries, runtime packages, documents and generated fragments must not. The copied full-bundle source was removed from the working tree; the prior full-copy commit remains on a remote feature branch and must not enter direct-main history.
