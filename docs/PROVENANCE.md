## Complete runtime and host inputs

The development build retains the entire official `usr/lib/chatgpt` tree under `host/application`, including the native Owl shell, `app.asar`, application libraries, the original runtime, and every original resource and plugin. Each architecture contains 3,760 files and 620 directories, with zero exclusions from this application tree. Its complete manifest is generated by streaming the checksum-verified `.deb`; packaging verifies every byte, mode, and directory against that manifest.

`runtime` is a relative alias into the retained `resources/cua_node` tree. That tree keeps all 2,260 files and 322 directories without source edits, tree shaking, export rewriting, dependency pruning, or instruction replacement. Shared files can contain other-platform branches: retaining them prevents changing the Linux implementation. `host/bin` and `host/plugins` expose relative aliases to the original companion executables and the complete `browser`, `chrome`, and `unified-computer-use` plugins. Their narrower 750-file inventory includes the Linux extension host, native messaging installer, original tool configuration, and turn-ended hook definitions. The aliases avoid storing duplicate runtimes. Presence of a hook definition remains distinct from registering it with an agent host.

Architecture-specific [application](../scripts/application-inventory.arm64.json), [runtime](../scripts/runtime-inventory.arm64.json), and [host](../scripts/host-inventory.arm64.json) inventories record every retained file, mode, symlink target, and SHA-256. The runtime and host indexes also record package exports, declarations, configuration identifiers, and dynamic document graphs. The build verifies the complete retained application and its aliases. The independent differential gate separately checks its untouched upstream extraction against the installed runtime. See [INVENTORY.md](INVENTORY.md) for both architecture records and indexed surfaces.

The app implements Linux-relevant IAB and host behavior in `app.asar`, which is retained unchanged. Its dependency graph is documented in [HOST-INVENTORY.md](HOST-INVENTORY.md). The build also exposes an original IAB declaration closure through a guarded extraction, separately from the intact archive and LCU's standalone adapter. Retaining the code does not establish that the adapter supplies all required application state and policies. Unresolved host behavior remains a blocker to full standalone parity.

## Ubuntu 24.04 system dependencies

Both pinned `.deb` control files declare the same dependency names; their minimum `libgcc-s1` versions differ by architecture. LCU translates the declaration to Ubuntu 24.04 package names and installs those packages individually, choosing `libglib2.0-bin` and `mesa-vulkan-drivers` from the upstream alternatives. It does not install the ChatGPT package, run its package-maintenance scripts, or add its OS desktop registrations.

The pinned runtime includes Playwright 1.57.0. Its original `cua_node/lib/node_modules/playwright-core/lib/server/registry/nativeDeps.js` maps the Ubuntu 24.04 GTK, GLib, accessibility, ALSA, and CUPS libraries to their `t64` package names; the ARM64 entry explicitly reuses the x64 lists. This file's SHA-256 is `9d3adab0fedfc5f6c48217582fe34624875dad22b3537925bc6f81140c94ed6a`. Ubuntu's official [ESYS](https://packages.ubuntu.com/noble/libtss2-esys-3.0.2-0t64), [MU](https://packages.ubuntu.com/noble/libtss2-mu-4.0.1-0t64), and [device transport](https://packages.ubuntu.com/noble/libtss2-tcti-device0t64) records supply the remaining TPM mappings and confirm `libssl3t64`.

[The installer](../scripts/install.py) and [verification image](../tests/Dockerfile) include the full mapped dependency set alongside the existing native X11/audio/session prerequisites. Source comparison and static list consistency checks passed. Fresh apt provisioning, ELF-loader checks, and an Owl launch with this revised dependency set remain unvalidated on both architectures. See [installation requirements](INSTALLATION.md#requirements) for the exact mapping and environment requirements.

## Instructions and launch integration

All 195 selected instruction resources are complete original files, including alternate modes and all resources under each declared guide root. Their 385 source/reference copies have identical bytes. The runtime uses its original copies. The build rejects missing or extra resources within those roots and any instruction edit. Standalone namespace and Linux-entrypoint notes are confined to the separate skill wrapper. See [INSTRUCTIONS.md](INSTRUCTIONS.md).

LCU executes the original `@oai/cua-repl/bin/cua-repl.mjs` and enables both surfaces by default. It preserves caller configuration, policies and metadata, selects its bundled executables, adds its module/trust paths and disables analytics by default. For a host without session metadata it creates a connection identity containing only session/turn routing IDs. That fallback does not manufacture approvals, model identity or original agent-turn lifecycle events.

Codex registration restores original tool visibility, routing, 120-second startup timeout and 25,000-token JavaScript output allowance through the bundled registration library. The actual Codex host is tested with an offline scripted model to verify agent-visible delivery. These tests do not measure a real model's task-success reliability.

Native actions work without an account in the isolated tests. External-browser actions retain upstream identity/authentication requirements. IAB and cloud providers have additional dependencies. See [BROWSER-HOST-PARITY.md](BROWSER-HOST-PARITY.md) for exact source paths and current blockers; do not describe this development build as complete parity.

## Distribution boundary

Architecture-specific release archives include the complete original OpenAI Linux application, its runtime and host code, and all agent-registration dependencies. The build fetches and verifies the official package and packages its unchanged application tree, source-checked extracted host declarations, LCU integration, and upstream notices. The installer verifies and copies these bundled files; its optional apt step provisions system libraries separately. The application/runtime has no download fallback and requires no `.deb`, npm, or build tool on the target machine. Generated archives live in `dist/` and are excluded from source commits. The repository's MIT license applies to LCU-owned code and the MIT Luda-derived packaging code; bundled dependencies retain their own terms.

The Luda code supplies registration, validation, account ownership handling, portable export, and provisioning of pinned upstream `skills` 1.7.0 / `add-mcp` 2.4.0. No Luda screenshot, input, accessibility, browser, or MCP engine is used.

Updating the runtime requires inspecting the new official package, updating complete inventories and checking integration changes, and rerunning both architecture tests. Do not remove integrity checks or enable another desktop engine as a fallback.
