# Dependency provenance

The macOS path reuses locally installed signed ChatGPT.app 26.917.62051 (`com.openai.codex`, Team ID `2DC432GLL2`), with the same CUA runtime version as Linux. Its separate `platforms.darwin` pins cover Apple Silicon only. LCU verifies the outer app and original Codex Computer Use helper signatures and required file hashes, then uses them in place. See [platform evidence](verification/platform-selection.md). The official Windows x64 MSIX 26.917.9434.0 has also been inspected and pinned; its native installed-app behavior was exercised in a disposable VM. See [Windows source evidence](verification/windows-source.md).

The Windows Store MSIX is pinned by SHA-256 `9892383820c5505997456bde8385810afadd6076ae7fff9e3835a48ca0555c98`. Its `app/resources/app.asar` member `.vite/build/main-BR_2NHW6.js` has SHA-256 `1f2b91cf92fc023fb2fa41e1c1d03698fa6e37354ecd07dd0cebd21337607b08`; byte range `[155346,165208)` is the original `Wre` native-pipe host (SHA-256 `3dae7a2bb89573e78dff25715efaf44dadbe7a7376c9243987d18d43b5f05247`). The Windows installer extracts that exact host block and six unchanged ASAR dependencies into the selected private LCU release. A thin entry starts and disposes it outside the original sandboxed Node REPL. The original helper, Sky service, pipe protocol, approval forwarding and CUA API stay unchanged; none of those extracted bytes enters Git or a thin archive.

The original app's `Noe` handler calls `Wre.closeActiveTurn({sessionId,turnId})` directly on app-server `turn/completed`; the standalone Node REPL and host are separate processes. LCU's Windows trusted-service wrapper forwards `nodeRepl.rpc('sky',...)` to the unchanged original Sky service, registers the original `addTurnEndedHandler`, and uses the original `nodeRepl.nativePipe` facility to send only real session/turn IDs over a random private lifetime pipe. The host calls unchanged `closeActiveTurn`; this signal neither routes CUA methods nor grants access. Installed candidates listed a live Notepad window and saved exact Unicode text to an existing file with an independent byte oracle. A matching Stop removed its helper, a stale Stop left a newer turn's helper intact, a matching Interrupt removed that helper, and MCP shutdown removed a third helper. The original `turn_ended` tool returned `{}` even when an earlier callback failed, so this conclusion rests on the independent helper-state oracle. See [Windows source evidence](verification/windows-source.md) for the guest boundary.

LCU installs the official ChatGPT Linux application 26.915.31945 as a private dependency on the target Linux machine. Its CUA runtime is 0.0.16/20260915001755-492f19756c31. The package URL template, ARM64 and amd64 SHA-256 digests, and a small architecture-specific critical-file hash set are in [runtime.lock.json](../runtime.lock.json). The digest is checked before extraction; this is an integrity pin, not independently verified package-signature authentication.

The inspected .deb control metadata says Package=chatgpt, Version=26.915.31945, with Architecture=arm64 or amd64. The app lives at usr/lib/chatgpt inside the package and contains the unchanged resources/cua_node runtime, resources/codex and resources/codex-code-mode-host, plugin tree, Electron application and original notices. LCU stages the complete package payload under its versioned managed prefix. It does not run the package maintainer scripts or register the app with apt.

The pinned package post-install script writes an OpenAI apt key/source and loads an AppArmor profile. That profile is bound to /usr/lib/chatgpt/ChatGPT, the original Electron UI executable, and grants userns to it. LCU launches the selected app's Node/REPL directly, without running that post-install script. Ubuntu 24.04.5 ARM64 and x86-64 guests with AppArmor active passed installed native fixtures and no-sign-in Chrome actions using LCU's relay; the x86-64 guest ran under KVM on physical AMD hardware. Process sampling found Node/REPL `unconfined`, Chrome and the extension host `chrome (unconfined)`, and nonblocking `bwrap` capability denials. Chrome launched without `--no-sandbox`. See the [exact verification record](verification/installed-app-2026-09-23.md).

The original Chrome provider and native messaging host come from `resources/plugins/openai-bundled/plugins/chrome` in this same installed app. Its `scripts/installManifest.mjs` registers native messaging; LCU copies that plugin to the target account's writable data directory during browser setup, runs the original installer there, and points the account's manifest at LCU's small relay. The relay locally enables the official extension's agent request label. The original `docs/chrome-troubleshooting.md` lines 31–38 directs a missing-extension user to the selected browser's exact `storeUrl` in `scripts/extension-ids.json` and requires permission before opening the store or management page. It provides no silent Web Store installation action; the desktop user must confirm installation or enablement in the browser. LCU prints the same official store link and preserves that browser confirmation boundary. [OpenAI's extension documentation](https://learn.chatgpt.com/docs/chrome-extension) gives its supported setup flow. [Google's Chrome Linux guide](https://support.google.com/chrome/answer/95346?hl=en) lists both x86-64 and ARM64 packages. Extension discovery alone does not prove browser action.

The shared harness client uses `@modelcontextprotocol/sdk` 1.30.0, pinned in `adapters/package-lock.json`; it delegates MCP protocol behavior to that SDK. The Pi extension uses the host Pi installation.

The build fetches separately pinned third-party agent registration tools defined in scripts/agent-tools/package-lock.json. Their temporary build Node is discarded; setup uses the selected official app Node. These tools and LCU code may appear in a thin archive, subject to their own licences. Original OpenAI app binaries, runtime packages, documents and generated fragments must not. The copied full-bundle source was removed from the working tree. The full-copy commit was removed from the new local main lineage, and its remote feature branch was deleted.
