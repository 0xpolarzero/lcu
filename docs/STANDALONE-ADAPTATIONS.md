# Standalone integration adaptations

LCU launches the original @oai/cua-repl server, original Sky/native services and original Chrome provider from one selected official application. Compatibility uses official identity/signature where applicable, supported platform/architecture, runtime metadata, required files, and recognized original host layout; selected versions are reported rather than checked against repository app-version/component-hash allowlists. It adds only the host integration needed outside the ChatGPT desktop application. The API, descriptions, schemas and upstream instruction files remain unchanged.

| Adaptation | LCU behavior | Boundary |
| --- | --- | --- |
| App selection | The selected app and observed version/runtime are recorded in the installation descriptor. Linux and Windows managed copies carry source-derived full-tree inventory identity. | No OpenAI files are rewritten or placed in the LCU archive; no repo app-version or component-hash allowlist is used for local selection. |
| macOS app selection | The platform resolver checks the official app/team identity and signatures, supported Apple Silicon architecture, runtime manifest, required files, and a recognized pair of original Codex tool paths, then links to the app in place. The original `SKY_CUA_SERVICE_PATH` selects the signed helper. | No app download, copy or re-signing. The current `26.924.22138` selection and MCP initialize/JS/reset check passed; the [record](verification/macos-current-app-2026-09-26.md) does not claim a new GUI or Chrome action. |
| Windows native host | The currently registered official Store package is validated by identity, publisher/signature, architecture, and required structure. Its observed version/runtime and source-derived inventory identify the intact private copy. The installer extracts required original host files from the selected app.asar into that LCU release, then starts the host outside the sandboxed node_repl process. A private one-operation lifetime signal forwards real `turn_ended` IDs to Wre's unchanged `closeActiveTurn`; Sky tool calls and approvals still use the original native pipe. | The original desktop calls `closeActiveTurn` in-process on `turn/completed`; standalone node_repl runs in another process, so that callback needs a local lifetime connection. The signal does not route CUA methods or grant approvals. Installed Windows completion and interruption cleanup still require the live gate. |
| Executable paths | The child environment points to the selected app's Node, node_repl, Codex CLI, module and plugin roots. | Explicit caller policy and sandbox settings survive. |
| CODEX_HOME | An explicit value is passed verbatim; otherwise Linux HOME is joined with .codex as the selected original Node host does. Empty trust entries are omitted. | Only the launched child environment changes; no user Codex configuration is edited. |
| Generic MCP ownership | A generated connection ID supplies routing identity only when a host supplies no request metadata. | It is not an account, model identity, approval, or real turn event. Per-call metadata takes precedence. |
| Desktop session | lcu-session selects one existing same-user XFCE X11 session, or direct mode uses the caller's GUI environment. | LCU does not create a desktop or VM. |
| Chrome opt-in and native host | Native computer use is the default and has no Chrome setup side effect. With explicit `--chrome`, LCU enables the original browser surface. Chrome setup copies the original plugin from the selected app into the target account's writable data directory because its installer writes beside its executable, runs that installer, then points the account's manifest at LCU's small relay. The relay changes only a fresh extension's `agentRequestHeaderEnabled: false` reply to `true`. | The original provider, host and extension still perform browser actions. LCU locally enables the website-visible `x-browser-agent` label and skips the Codex account feature-gate lookup on this path. Original MCP site approval remains active. The account-level manifest also affects other apps using that extension; the extension persists the header state in its profile. |
| Browser account initialization | LCU defaults the original `BROWSER_USE_DISABLE_AMBIENT_NETWORK` option to `1`, preserving an explicit caller override. | Account identity and telemetry initialization are skipped; original site approvals remain active. [Offline browser actions](verification/no-account-network-2026-09-24.md) passed with this option. |
| Agent delivery | Setup registers the fixed original MCP policy and lifecycle hooks, and no skill, as in official Codex's `unified-computer-use` plugin. The model gets the original instructions only through the MCP server, tool descriptions and tool results. Setup removes the `lcu` skill registered by earlier LCU versions. | No OpenAI documents are copied. Portable exports carry bootstrap metadata only. Generic hosts must honor the exported contract. See [instruction delivery](INSTRUCTIONS.md). |
| Instruction modes | Default `lcu` selects the original computer surface; `lcu --chrome` selects browser and computer, and the runtime returns the original browser guidance. | The in-app browser and MCP Apps backends of the official browser surface exist only inside the ChatGPT app. LCU does not install the separate `control-chrome` plugin skill, whose `setupBrowserRuntime()`/`agent.browsers` mode does not apply to unified CUA. |
| Pi delivery | A shared official MCP SDK client forwards original tool schemas/descriptions, initialization instructions, results and per-turn metadata. Pi registers `js`/`js_reset` as native tools and invokes the original cleanup after its complete agent turn. | MCP stays internal. Pi supports text/images and empty-form approvals; it rejects unsupported result blocks and cancels unsupported approval forms. See [adapters](ADAPTERS.md). |
| OMP delivery | A generated native plugin wraps the Pi adapter, preserving OMP prompt blocks and the selected command. OMP's own linker owns user-profile registration; project scope is rejected. | Experimental harness integration; [evidence](verification/omp-compatibility-2026-09-28.md) does not extend existing platform claims. |
| Hermes delivery | A native Python plugin supplies host lifecycle context to a private Node bridge using the shared MCP SDK client. Setup stages only its own plugin tree and calls the native enable command. | Profile scope only. The model receives original initialization instructions and tool descriptors each turn; no skill is registered and no original documents are copied. See [host evidence and limits](verification/hermes-harness-2026-09-28.md). |
| macOS native turn cleanup | The original Sky service is forwarded unchanged. Its original turn-ended callback signals a private lifetime host, which invokes the selected signed `SkyComputerUseClient turn-ended` command with exact session/turn identifiers. Failed notifications are retried before further Sky requests. | The original MCP runtime and a recording command verified Stop, Interrupt and failure retry. Visible cursor removal and native stale-turn behavior remain unverified; see [cursor lifecycle evidence](verification/macos-cursor-lifecycle-2026-09-27.md). |
| Explicit site grants | A caller may supply exact user-authorized origins; the adapter answers only matching original origin-approval requests. | No implicit grant, wildcard policy or setup-time OS permission bypass. Without a grant, the original request goes to the harness UI. |

The inspected Linux app package's post-install script would register an apt source and apply an AppArmor profile for /usr/lib/chatgpt/ChatGPT, its Electron UI. LCU does not run that script or launch that UI. The installed ARM64 and x86-64 thin archives passed native fixtures and no-sign-in Chrome actions in Ubuntu 24.04.5 guests with AppArmor active; the x86-64 guest ran under KVM on physical AMD hardware. See the [verification record](verification/installed-app-2026-09-23.md).

The old embedded-browser host, extraction script, protocol handler and renderer shims have been removed from the active source. The active launcher returns migration errors for their CLI flags. The full-copy commit was removed from the new local main lineage, and its remote feature branch was deleted.
